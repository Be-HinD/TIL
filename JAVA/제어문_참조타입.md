# 2주차 WrapUp

### 변수

- 선언 → 초기화 → 사용 순서 지킬 것
- 지역변수만 자동 초기화 안 됨, 나머지는 됨
- 스코프: 선언된 `{}` 블록 안에서만 유효
- 변하지 않는 값엔 `final` 붙이는 습관

### 기본 타입

- 정수는 `int`, 21억 넘으면 `long`
- 실수는 `double`, 돈 계산은 무조건 `BigDecimal`
- 문자열 비교는 항상 `equals()`, `==` 쓰면 주소 비교라 버그남
- `String`은 불변 → `replace()` 결과 안 받으면 원본 그대로

### 입출력

- `System.out.println` 기본, 소수점 자릿수 맞출 때 `printf`
- `Scanner`는 학습/테스트용, 실무에선 콘솔 입력 거의 안 씀
- 반복문 안에서 문자열 합칠 땐 `StringBuilder` 필수

### 연산자

- 정수 나눗셈은 소수점 버림 → 필요하면 `(double)` 캐스팅
- `0` 나누기: 정수는 예외 터짐, 실수는 `Infinity`/`NaN` 조용히 퍼짐
- `&&` 왼쪽에 null 체크 먼저 → 단축 평가로 NPE 방지
- 우선순위 외우지 말고 헷갈리면 괄호

# 제어문

> 프로그램의 핵심은 제어문을 다루는 것.
모든 프로그램은 특정 동작을 수행하기 위함이며, 그 내부는 여러 제어문으로 구성되어 있다.
> 

제어문에는 **조건문**과 **반복문**이 있다.

---

## 조건문: if, switch

주어진 조건에 따라 실행할 행동을 미리 정의해두기 위해 사용하는 문법.

### if

```java
if (조건식) {
    // 참일 때
} else if (조건식) {
    // 추가 조건
} else {
    // 거짓일 때
}
```

- `조건식`은 반드시 `true` / `false`만 나오는 표현이어야 한다
- `else if`로 여러 조건을 중첩할 수 있다
- 실무 팁 : 한줄일 경우 블록{} 을 생략할 수 있지만, 작성해주는게 가독성이 더 좋음.
- **TIP - 조건 반전으로 중첩 줄이기 (Early Return)**
    
    ```jsx
    // ❌ 중첩이 깊어질수록 읽기 어려움
    public void process(User user) {
        if (user != null) {
            if (user.isActive()) {
                if (user.hasPermission()) {
                    // 실제 로직
                }
            }
        }
    }
    
    // ✅ 조건 반전으로 일찍 탈출
    public void process(User user) {
        if (user == null) return;
        if (!user.isActive()) return;
        if (!user.hasPermission()) return;
    
        // 실제 로직
    }
    ```
    
- **TIP - 조건식 변수로 추출하여 가독성 높이기**
    
    ```jsx
    // ❌ 조건만 봐서는 의도를 알기 어려움
    if (user.getAge() >= 19 && !user.isBanned() && user.getPoint() > 1000) { ... }
    
    // ✅ 의도가 드러나는 변수명으로 추출
    boolean isAdult = user.getAge() >= 19;
    boolean isEligible = !user.isBanned() && user.getPoint() > 1000;
    
    if (isAdult && isEligible) { ... }
    ```
    

### switch

문자열, 정수 등 **특정 값을 기준으로 분기**할 때 사용한다.

```java
switch (day) {
    case "MON":
    case "TUE":
        System.out.println("평일");  // MON도 여기 탄다
        break;
    case "SAT":
        System.out.println("토요일");
        // break 없으면 SUN까지 실행됨 ← 실수 1위
    case "SUN":
        System.out.println("주말");
}
```

> **핵심 주의사항**: `break` 유무에 따라 동작이 완전히 달라진다.
의도하지 않은 fall-through는 찾기 어려운 버그로 이어진다.
실무 팁 : 잘 사용하지 않는 것 같음.
>

## 반복문: for, while, do-while

미리 정의한 동작을 정해진 횟수 또는 조건에 따라 반복하는 문법.

### for

횟수가 정해진 반복에 주로 사용한다.

```java
// 초기화식 ; 조건식 ; 증감식
for (int i = 0; i < 5; i++) {
    System.out.println(i);
}
```

- 세 요소(초기화식, 조건식, 증감식) 모두 생략 가능
- 중첩 for문 사용 시 바깥 루프 1회당 안쪽 루프가 전체 실행됨

### while

조건식을 기준으로 반복 횟수가 유동적일 때 사용한다.

```java
while (조건식) {
    // 조건이 true인 동안 반복
}
```

### do-while

```java
do {
    // 최소 1번은 무조건 실행
} while (조건식);
```

> 실무에서 자주 쓰이지 않으니 어떤 것인지 정도만 알아두면 충분하다.
> 

### break / continue

반복문 안에서 흐름을 더 유연하게 제어할 수 있다.

| 키워드 | 동작 |
| --- | --- |
| `break` | 반복문 즉시 탈출 |
| `continue` | 현재 회차를 건너뛰고 다음 반복으로 |

> **무한루프 주의**: 반복문 작성 시 항상 탈출 조건이 있는지 확인하라.
실제로 돌려보면 바로 알 수 있지만, 서버에서 터지면 얘기가 달라진다.
>

## 기본 타입 vs 참조 타입

```
[스택]                      [힙]
┌──────────────┐           ┌──────────────────┐
│ int a = 10   │           │                  │
│ (값 직접 저장)│           │  실제 객체 데이터  │
├──────────────┤           │                  │
│ String s     │ ────────→ │   "hello"        │
│ (주소 저장)   │           │                  │
└──────────────┘           └──────────────────┘
```

- 모든 변수는 **스택**에 저장된다
- 기본 타입: 스택에 **값 자체** 저장
- 참조 타입: 스택에 **힙의 주소** 저장, 실제 데이터는 힙에 존재

## null

참조 타입은 아무 주소도 가지지 않는 상태인 `null`을 가질 수 있다.

### 탄생 배경

1965년 **토니 호어**가 ALGOL W 언어 설계 시 도입.
당시 목적: *"참조값이 유효하지 않음을 컴파일러가 쉽게 체크하게 하려고"*

### 비하인드

2009년 토니 호어가 컨퍼런스에서 직접 발언:

> "I call it my billion-dollar mistake" — 10억 달러짜리 실수였다.
> 

이유:

- null 체크 안 한 코드가 전 세계에서 수십 년간 장애를 냄
- 컴파일 타임에 잡을 수 없고 **런타임에 터짐**
- 방어 코드(`if != null`)가 코드베이스 전체에 퍼짐

### NPE 방어 패턴

```java
// ❌ status가 null이면 NPE
if (status.equals("ACTIVE")) { ... }

// ✅ status가 null이어도 안 터짐
if ("ACTIVE".equals(status)) { ... }
```

> **원칙**: 비교 시 **null이 될 수 있는 변수**를 오른쪽에 둔다.
> 

Java 8 이후엔 `Optional`로 null을 명시적으로 다루는 방향으로 흘러갔다.
지금 당장 쓰지 않더라도 코드에서 보이면 *"null을 안전하게 다루는 장치"* 정도로 이해해두면 된다.

# 5-2 배열

## 배열 (Array)

배열은 **같은 타입의 값을 연속으로 저장하는 자료구조**다.

---

## 1. 배열은 객체다

Java에서 배열은 **참조 타입**이다.
즉, 변수에 값이 직접 들어가는 게 아니라 **힙(Heap) 영역에 생성된 객체의 주소**가 들어간다.

```jsx
[스택]               [힙]
┌──────────┐        ┌─────────────────────┐
│ scores   │──────→ │ [90][85][70][95][100]│
│ (주소값) │        └─────────────────────┘
└──────────┘
```

기본 타입과 비교하면 차이가 명확하다.

```java
int a = 10;         // 스택에 값 10이 직접 저장
int[] scores = ...; // 스택에 힙 주소가 저장, 실제 데이터는 힙에
```

---

## 2. 배열 생성 (생성자)

배열 생성 방법은 두 가지다.

```java
// 방법 1: 크기만 지정 — 기본값으로 초기화됨
int[] scores = new int[5];
// [0, 0, 0, 0, 0]

// 방법 2: 값을 직접 지정
int[] scores = {90, 85, 70, 95, 100};
```

`new int[5]`로 생성하면 타입별 기본값으로 자동 초기화된다.

| 타입 | 기본값 |
| --- | --- |
| `int`, `long` 등 정수형 | `0` |
| `double`, `float` 등 실수형 | `0.0` |
| `boolean` | `false` |
| 참조 타입 (`String` 등) | `null` |

> 배열 생성 시 크기는 **고정**된다. 한 번 정하면 늘리거나 줄일 수 없다.
> 

---

## 3. 인덱스

배열의 각 요소는 **인덱스(index)**로 접근한다. 인덱스는 **0부터** 시작한다.

```jsx
scores = [90][85][70][95][100]
인덱스     0   1   2   3   4   // 인덱스는 항상 `0`부터 시작
```

```java
int[] scores = {90, 85, 70, 95, 100};

System.out.println(scores[0]); // 90 — 첫 번째
System.out.println(scores[4]); // 100 — 마지막

scores[2] = 99; // 값 변경
```

마지막 인덱스는 `배열.length - 1`이다.

```java
System.out.println(scores.length);         // 5
System.out.println(scores[scores.length - 1]); // 100 — 마지막 요소
```

### 흔한 실수 — ArrayIndexOutOfBoundsException

```java
int[] scores = {90, 85, 70, 95, 100};

// ❌ 길이가 5인데 인덱스 5 접근 → 런타임 예외 발생
System.out.println(scores[5]);

// ❌ for문에서 자주 발생
for (int i = 0; i <= scores.length; i++) { // <= 가 문제
    System.out.println(scores[i]); // 마지막에 터짐
}

// ✅ 올바른 범위
for (int i = 0; i < scores.length; i++) {
    System.out.println(scores[i]);
}
```

---

## 4. 배열이 객체이기 때문에 발생하는 함정

배열 변수는 **주소를 저장**한다. 변수를 다른 변수에 대입하면 **같은 힙 객체를 가리키게 된다.**

```java
int[] a = {1, 2, 3};
int[] b = a;         // 주소를 복사한 것

b[0] = 99;

System.out.println(a[0]); // 99 — a도 바뀐다!
```

```jsx
[스택]          [힙]
┌───┐          ┌───────────┐
│ a │──────→   │ [99][2][3]│
├───┤     ↗   └───────────┘
│ b │──────
└───┘
```

b를 바꿨는데 a도 바뀌는 이유는, **둘이 같은 힙 객체를 가리키고 있기 때문**이다.

배열을 독립적으로 복사하려면 단순 대입이 아닌 별도 방법이 필요하다.

```java
int[] b = Arrays.copyOf(a, a.length); // 새로운 배열 객체 생성
```

## 5. 기본 타입 배열 vs 참조 타입 배열

배열 자체는 항상 힙에 저장되지만,
**배열 안에 뭐가 들어가느냐**가 기본 타입과 참조 타입에서 다르다.

### 기본 타입 배열 — int[]

```java
int[] scores = {90, 85, 70};
```

```jsx
[스택]              [힙]
┌────────┐         ┌────┬────┬────┐
│ scores │────────→│ 90 │ 85 │ 70 │
└────────┘         └────┴────┴────┘
값이 직접 저장됨
```

배열 안에 **값 자체**가 들어간다.

---

### 참조 타입 배열 — String[]

```java
String[] names = {"홍길동", "이순신", "강감찬"};
```

```
[스택]
┌─────────┐
│  names  │
└────┬────┘
     │
     ↓
[힙]
┌─────────────────────────────────────────┐
│                                         │
│  배열 객체                               │
│  ┌──────────┬──────────┬──────────┐     │
│  │  addr_0  │  addr_1  │  addr_2  │     │
│  └────┬─────┴────┬─────┴────┬─────┘     │
│       │          │          │           │
│       ↓          ↓          ↓           │
│   "홍길동"    "이순신"    "강감찬"        │
│  (String)    (String)    (String)       │
│                                         │
└─────────────────────────────────────────┘
```

배열 안에 **객체의 주소**가 들어간다.
실제 문자열은 힙의 다른 곳에 따로 존재한다.

---

### 핵심 차이 한 줄 요약

|  | `int[]` | `String[]` |
| --- | --- | --- |
| 배열 칸에 저장되는 것 | 값 자체 | 객체 주소 |
| 초기화 안 하면 | `0` | `null` |

```java
int[] scores = new int[3];
String[] names = new String[3];

System.out.println(scores[0]); // 0
System.out.println(names[0]);  // null ← 주소가 없는 상태

// null인 상태에서 메서드 호출하면 NullPointerException
System.out.println(names[0].length()); // 터짐
```

> String[] 다루기 전에 null 체크 습관을 들여라.
배열 초기화를 빠뜨리는 실수가 NPE의 흔한 원인이다.
>
